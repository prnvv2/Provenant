# Canonicalisation

Every hash and signature in Provenant is computed over canonical bytes. If two
implementations disagree about those bytes, they disagree about every root, and
verification fails for reasons that look like tampering. This document defines
exactly what Provenant v0.1 produces and accepts.

## Profile

Provenant uses a **subset of RFC 8785 (JSON Canonicalization Scheme)**:

1. Object keys sorted ascending by UTF-16 code unit. This is JavaScript's native
   string ordering, so `"B"` (0x42) sorts before `"a"` (0x61).
2. No whitespace anywhere.
3. Arrays keep their order.
4. Strings escaped as JSON, output as UTF-8.
5. Numbers as ES6 `Number::toString` — which is what RFC 8785 specifies and what
   `JSON.stringify` implements.

## Rejected inputs

The canonicaliser **throws** rather than guessing. Each of these would otherwise
produce bytes that differ between implementations or silently lose data:

| Input | Why it is rejected |
|---|---|
| `undefined` property value | `JSON.stringify` drops the key; a signature would cover a different object than the caller passed |
| `NaN`, `Infinity`, `-Infinity` | not representable in JSON |
| `Date` object | serialisation is locale- and library-dependent; convert to an RFC 3339 string first |
| function, symbol | not data |

## Deliberate gaps

Not implemented from RFC 8785, because nothing in the event schema uses them:

- Lone surrogates in strings (RFC 8785 requires specific handling; Provenant's
  event fields are ASCII-or-valid-UTF-8 paths, commands and digests).
- Numbers outside the IEEE-754 double range. All numeric fields in the event
  schema are small integers (`v`, `seq`, `bytes`, `size`).

An implementation that needs those cases should use a full RFC 8785 library; the
outputs agree for everything in `spec/event-v1.md`.

## Digest references

Hashes appear in events as strings, never raw bytes:

```
"sha256:" ‖ lowercase hex          e.g. "sha256:27008480afd7…"
```

Base64 is used only for a checkpoint `root` and for signatures and public keys,
where the value is not a reference.

## Test vectors

`spec/vectors/merkle.json` is generated by `scripts/gen_vectors.py`, an
independent Python implementation of RFC 6962, and is used to test the
JavaScript tree. Canonicalisation cases live in `test/core.test.js`; the
important ones are key ordering, insertion-order independence, and each rejected
input above.
