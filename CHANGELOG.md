# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project uses
semantic versioning once it reaches 1.0.

## [0.1.0] — unreleased

First release: a local policy gate and tamper-evident lineage log for Claude Code.

### Added

- **Policy gate.** Every tool call is classified into one of 16 harness-independent
  action classes and decided as `allow`, `ask` or `deny` before it runs. Rules are
  ordered JSON with class, taint and resource conditions; the first match wins.
- **Taint tracking.** A session starts `trusted` and drops to `external` once the
  agent reads content it did not author. Risky classes then require approval.
- **Signed lineage.** Each decision becomes a DSSE-signed event in an append-only
  JSONL log, hash-chained by `parent` and committed to an RFC 6962 Merkle tree.
  A machine key certifies each per-session signing key.
- **Verification.** `provenant verify` checks event signatures, the session-key
  certificate, sequence and chain continuity, the signed checkpoint root, and an
  inclusion proof for every leaf, naming the first event that fails.
- **Checkpoints.** `provenant checkpoint` signs the current root and appends it to
  `checkpoints/roots.jsonl` for copying off the machine.
- **Claude Code adapter** for `SessionStart`, `UserPromptSubmit`, `PreToolUse`,
  `PostToolUse` and `Stop`, with a JSON permission decision and a
  `PROVENANT_HOOK_MODE=exitcode` fallback.
- **CLI:** `init`, `status`, `log`, `verify`, `checkpoint`, `policy`, `explain`,
  `doctor`.
- **Merkle test vectors** generated by an independent Python implementation
  (`scripts/gen_vectors.py`), plus property tests over random append sequences.
- **Benchmark** (`npm run bench`) reporting in-process and full-hook latency.

### Known limitations

- Detects log tampering rather than preventing it: the agent runs as the same OS
  user. Keep a checkpoint root off the machine. See `docs/adr/0003-key-custody-v01.md`.
- Claude Code only; OpenCode and Codex are planned for v0.2.
- `ask` uses the harness prompt and is not cryptographically bound to the action.
- The shell classifier is a tokeniser, not a shell (`docs/adr/0004-shell-classification.md`).
- Full-hook latency is dominated by Node's process start (~80 ms on Windows);
  v0.2 moves the hook client to a compiled binary.
